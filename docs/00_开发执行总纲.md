## 1. 项目一句话

在 Windows 桌面角落常驻一个 360×480 的小窗：自动打怪 → 装备带着光柱喷涌掉落 → 自动熔炼成金币 → 金币用于升级、科技树、信贷，并支付每 100 层的门票 → 多层转生，无限成长。几天不看也零损失。美术风格为「镀金债契 · 骨白版画」：黑底骨白木刻主体，配荧光刻线特效。

## 4. 全局工程规范（所有任务通用）

1. **GDScript 静态类型**：所有变量、参数、返回值都写类型。`class_name` 采用 PascalCase，文件名与类名一致。
2. **Sim 隔离**：`simulation/`、`offline/`、`core/` 中**禁止**引用 `Node`、`SceneTree` 或任何渲染 API。表现层只能读 Sim；修改 Sim 只能通过 `Command`。
3. **确定性**：随机数只能来自 `SimRng`，分为 `combat`、`loot`、`collection` 三条种子流。同一个种子、同样的输入，必须得到同样的结果，这一点需要写测试验证。
4. **数值域**：会无限膨胀的量（伤害、血量、金币、债务、灵魂、托管余额）一律用 log10 存储，并且只能通过 `Num` 的静态函数运算。概率、攻速、计数器这类有上限的量**禁止**放进 log 域（02 号文件 §1.1）。
5. **参数**：所有可调常数都放在 `content/balance.tres`，代码里禁止硬编码数值常数。初始值取自 02 号文件 §1–§7。
6. **时间**：战斗用 10Hz 的 Sim tick；研究队列、离线结算和收藏判定用 Unix 时间戳。
7. **存档**：使用带 `version` 字段的 JSON，写入方式是先写 tmp 文件再 rename；图鉴单独存档（第二阶段）。
8. **测试**：每个任务包都要在 `tests/` 中补充测试，`godot --headless --script res://tests/run_all.gd` 必须全部通过。
9. **提交**：每完成一个任务包提交一次，提交信息格式为 `[WP-编号] 摘要`；美术资产必须先通过 `verify_manifest`。

## 6. 执行模型行为规则

### 6.1 必须停下来询问项目负责人的情况
1. 任何闸门（Gate-1、U1、U2）没有通过，或需要人工批准。
2. 需要修改**冻结项**：玩法决策 Q1–Q36、公式结构、色彩 HEX 值、画风、工具选择、目录结构、本文件。
3. 发现文档之间互相矛盾，且 §0 的裁决规则无法解决。
4. 需要花钱（API 调用超出预算、购买素材或软件）、注册账号，或需要安装本文件没有列出的软件。
5. 某项许可无法确认，包括 Megascans 的单个资产页面、Pixel Composer Demo 的 EULA、OpenAI 条款。
6. 同一个任务包连续 3 次验收失败。

### 6.2 可以自主决定的事
- 函数和私有变量的命名、内部数据结构、代码组织方式（只要不违反 §4）。
- `balance.tres` 中的参数取值，但必须有模拟数据支撑，并写进报告。
- UI 的具体像素排布，但必须在 03 号文件 §02.1 的布局范围内。
- 特效的时长和粒子数，但必须在 03 号文件 §02.5 给出的范围和上限内。

### 6.3 禁止事项
- 在 `simulation/` 中引用 Node 或任何渲染 API；在 Sim 中使用 `randf()` 这类全局随机数。
- 把未经加工的原始素材放进 `assets/`；绕过 `verify_manifest`。
- 使用 PixelFX 的 `gallery/fonts`；把 Megascans 的原始素材提交到公开仓库。
- 用 AI 生成 UI、文字、边框或截图类素材。
- 在没有设置密钥和预算的情况下调用 OpenAI API；提高 `ART_BUDGET_USD`。
- 为了让测试通过而修改测试的期望值，除非测试本身与规格不符，并且已经报告。
